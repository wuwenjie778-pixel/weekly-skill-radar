# GitHub Skill 每周热门榜自动化项目设计

## 1. 目标

构建一个无需自有服务器、无需付费服务的自动化项目。项目每周一北京时间 08:00 在 GitHub Actions 中运行，发现公开 GitHub 仓库中的 `SKILL.md`，并生成以下中文榜单：

- 全站热门 Skill：10 个
- 美术设计 Skill：10 个
- Photoshop Skill：5 个
- Illustrator Skill：5 个

同一个 Skill 可以进入多个榜单。榜单从第二次成功运行开始按相邻两次每周快照的 Star 净增长量排序。第一次运行用于建立基线，并按总 Star 输出参考榜单。

## 2. 范围

### 包含

- 公开 GitHub 仓库中至少存在一个 `SKILL.md` 的项目
- GitHub API 候选发现、元数据采集和内容采集
- 每周 Star 快照及增长量计算
- 基于中英文关键词的专业分类
- Markdown 历史周报和最新周报
- GitHub Actions 定时及手动运行
- 自动提交报告和状态更新
- 自动化测试和本地运行说明

### 不包含

- 私有仓库
- AI 模型分类或摘要
- 邮件、Slack、微信等外部通知
- Web 管理后台或数据库服务
- GH Archive、BigQuery 等外部数据源

## 3. 热度定义

热度使用相邻两次成功周快照之间的 Star 净增长：

```text
weekly_star_growth = current_total_stars - previous_total_stars
```

该值反映一周观察窗口内的净增长，取消 Star 会抵消新增 Star。GitHub API 不提供针对所有候选仓库的单一全局周增量接口，因此使用持久化快照可在不引入外部数据服务的前提下稳定运行。

- 首次成功运行：保存基线，榜单按总 Star 降序排列，并醒目标注“基线初始化，非周增长榜”。
- 后续成功运行：按周 Star 净增长降序排列。
- 增长量相同：依次按总 Star、最近更新时间、仓库全名排序，保证输出稳定。
- 失败运行：不更新快照，因此下一次成功运行会与上一次成功快照比较。

## 4. 系统架构

项目采用 Python 命令行程序，由 GitHub Actions 调度。模块边界如下：

1. **候选发现器**：使用 GitHub Code Search 的多组查询发现包含 `SKILL.md` 的公开仓库，并与历史候选索引合并。
2. **GitHub 客户端**：统一处理认证、分页、超时、重试、速率限制和响应解析。
3. **仓库采集器**：读取仓库元数据、Topics、默认分支及一个或多个 `SKILL.md` 的路径和正文。
4. **分类器**：加载 YAML 规则，对仓库名、简介、Topics、文件路径和 `SKILL.md` 正文进行加权匹配。
5. **快照管理器**：读取上一次成功状态、计算增量、保存当前状态，并处理失效候选。
6. **排行生成器**：产生四个榜单，实施稳定排序及数量限制。
7. **报告渲染器**：生成当周历史报告和 `LATEST.md`。
8. **工作流**：每周定时或人工触发程序，在验证成功后提交报告、索引和快照。

各模块通过明确的数据对象传递结果，GitHub 访问、分类、排名和渲染可以独立测试与替换。

## 5. 数据流

每次运行按以下顺序进行：

1. 加载分类配置、候选索引和上次成功快照。
2. 通过多组分页搜索发现新候选，与已有候选去重合并。
3. 获取候选仓库元数据和 `SKILL.md` 内容。
4. 移除确认已删除、转为私有或不再包含 `SKILL.md` 的候选；暂时性网络失败不触发删除。
5. 计算当前总 Star 与上次成功快照的差值。
6. 运行分类器，保留类别、分数和命中理由。
7. 生成四个榜单。专业榜不足目标数量时按实际数量输出，不用无关项目补齐。
8. 先将状态与报告写入临时位置并完成校验，再原子替换正式文件。
9. GitHub Actions 提交变更；没有内容变化时正常结束且不产生空提交。

## 6. 候选发现策略

GitHub Code Search 单条查询存在结果上限，且不能可靠地按仓库创建时间切片。发现器使用多组可配置查询并合并分页结果：通用的 `filename:SKILL.md` 查询用于获取最相关和最近索引的结果；Agent、Codex、Claude 等生态词查询用于扩大通用 Skill 覆盖；design、art、Photoshop、Illustrator 等领域词查询用于提高专业榜覆盖。所有查询均面向全部公开所有者，不限定组织或仓库白名单。搜索结果只用于增加候选，历史候选不会因某次搜索没有返回而立即消失。

为控制 API 用量：

- 搜索查询组保存在配置文件中，可在不改程序的情况下扩展；
- 候选索引持久化到仓库中；
- 优先刷新活跃或曾有 Star 增长的项目；
- 对长期不活跃项目降低正文刷新频率，但仍刷新用于排行的 Star 元数据；
- 缓存内容指纹，文件未变时复用分类结果；
- API 接近限额时遵照响应头等待，无法在本次工作流时限内恢复时安全失败。

“所有公开仓库”表示搜索不限制 GitHub 所有者，是持续发现目标；不承诺突破 GitHub 搜索索引和单查询结果上限而绝对穷尽。通过多查询覆盖与每周合并候选索引逐步提高覆盖率。

## 7. 分类规则

分类配置保存在 `config/categories.yml`，无需修改程序即可调整关键词、排除词、字段权重和入选阈值。

匹配字段包括：仓库名称、仓库简介、Topics、`SKILL.md` 路径和正文。强相关词可单独触发，模糊词必须与上下文词组合出现。报告保存可读的命中理由。

### 美术设计

覆盖美术、视觉设计、平面设计、插画、绘画、配色、排版、品牌、海报、图像生成、3D、UI/UX 及对应英文表达。

### Photoshop

优先使用 `Photoshop`、`Adobe Photoshop`、`PSD`、修图、抠图和图像合成等强相关词。普通的 `PS` 不单独触发分类。

### Illustrator

使用 `Adobe Illustrator`、矢量设计、vector graphics、AI artwork、SVG 编辑等词或组合。普通的 `AI` 不单独触发分类。

## 8. 输出

历史周报路径采用 `reports/YYYY-MM-DD.md`，仓库根目录的 `LATEST.md` 始终保存最新一期完整榜单内容。

每个榜单条目展示：

- 排名
- Skill 或仓库名称及 GitHub 链接
- 本周 Star 净增长
- 当前总 Star
- 中文简介；没有可靠中文内容时保留原始简介，不调用机器翻译服务
- `SKILL.md` 路径
- 专业榜分类命中理由
- 仓库最近更新时间

报告头部记录统计窗口、生成时间、候选数量、成功采集数量、榜单口径及是否为首次基线。报告尾部记录跳过项和非致命警告摘要。

状态文件采用 JSON，至少包含仓库唯一标识、全名、URL、上次 Star 数、快照时间、有效性、内容指纹、分类结果和最近成功检查时间。状态文件属于程序数据，不要求人工编辑。

## 9. 自动化与权限

GitHub Actions 工作流支持：

- 定时触发：UTC 周一 00:00，即北京时间周一 08:00；
- `workflow_dispatch` 手动触发；
- 并发锁：同一时间只允许一个榜单任务更新状态；
- 最小权限：仅授予 `contents: write`；
- 使用 Actions 内置 `GITHUB_TOKEN`，不要求用户配置额外密钥；
- 固定 Python 主版本和依赖版本，降低环境漂移风险；
- 仅当测试、采集和报告校验全部成功后提交文件。

## 10. 错误处理

- 网络错误、5xx 和允许重试的限流响应采用带抖动的指数退避。
- 单仓库暂时读取失败时保留其历史状态，本次不参与需要最新数据的排行，并在报告中记警告。
- 只有明确的 404、仓库私有化或确认缺少 `SKILL.md` 才将候选标记失效。
- 核心搜索完全失败、旧快照无法解析、结果校验失败或 API 配额无法恢复时，工作流失败且不覆盖上一期有效报告和快照。
- 写入使用临时文件与替换流程，避免部分输出污染正式状态。
- 自动提交发生冲突时工作流失败并保留日志，不强制覆盖人工修改。

## 11. 测试与验收

单元测试覆盖：

- 首次基线与后续 Star 差值
- Star 减少和相同分数的稳定排序
- 中英文关键词、强弱词组合及排除规则
- `PS`、`AI` 等歧义缩写不会单独误判
- 同一项目进入多个榜单
- 候选失效与暂时失败的差异处理
- GitHub 分页、重试和限流响应
- Markdown 报告内容和文件命名

集成测试使用固定 API 响应样本，不依赖真实 GitHub 网络。部署后的手动工作流用于端到端验收。

项目完成的验收标准：

1. 本地测试全部通过。
2. 手动运行能建立基线并生成四类 Markdown 榜单。
3. 第二次使用测试快照运行时能正确计算周增长并排序。
4. GitHub Actions 工作流具备每周定时、手动触发、最小写权限和自动提交能力。
5. README 清楚说明部署、首次运行、调整分类词和排障方法。

## 12. 已知限制

- 周增量是相邻成功快照的 Star 净变化，不是对所有新增与取消 Star 事件的逐条审计。
- 第一次运行没有历史快照，因此不能生成真实周增长榜。
- GitHub 搜索索引、单查询结果上限和 API 限流会影响候选覆盖率；多组查询和持久化索引用于逐周改善覆盖。
- 关键词分类可解释且免费，但不具备语义模型的全部理解能力；分类规则应根据实际周报持续微调。
- 仓库包含多个 `SKILL.md` 时，初版以仓库作为排行单位，报告列出代表性文件路径，避免同一仓库凭多个文件重复占据同一榜单。
